# Weed Detector — MVP детекции сорняков на снимках с дрона

Хакатонный MVP: детекция сорняков (YOLOv8) на аэрофотоснимках с полей,
с тайловым (tiled) инференсом для больших UAV-изображений и веб-демо на Streamlit.

## Данные

Исходный датасет `Сорняки/<Вид сорняка>/<Фаза роста>/*.jpg` — это
классификационный набор (кропы отдельных растений), **без bounding box
разметки**. Чтобы получить рабочий детектор, `src/prepare_dataset.py`
автоматически генерирует псевдо-bbox для каждого фото: растение
сегментируется по индексу избыточной зелени (ExG) с порогом Отсу,
берётся bounding rect найденного объекта (с fallback на центральную
область кадра, если сегментация не удалась). Классы детектора = виды
сорняков.

`Поля/*.JPG` — пять реальных снимков с дрона DJI (4096×3072), без
разметки. Для обучения не используются (нет меток), но служат тестовым
набором для проверки tiled-инференса на настоящих UAV-кадрах — именно на
них обнаружился domain-shift, описанный в разделе «Известные ограничения».

## Установка

```bash
pip install -r requirements.txt
```

## Подготовка датасета (YOLO-формат)

```bash
python src/prepare_dataset.py
```

Создаёт `data/images/{train,val}`, `data/labels/{train,val}` и `data/data.yaml`.

## Обучение baseline-модели

```bash
python src/train.py
```

Опции: `--epochs`, `--imgsz`, `--batch`, `--device` (по умолчанию `cpu`).
Лучшие веса сохраняются в `models/best.pt`.

## Проверка инференса из консоли

```bash
python src/inference.py path/to/image.jpg 0.25 tiled
```

Сохранит `path/to/image_pred.jpg` и напечатает статистику (кол-во по
классам, total detections, weed coverage %, время обработки).

## Веб-демо

```bash
streamlit run app.py
```

Три вкладки:

- **📷 Фото / снимок** — загрузка изображения → оригинал → обработанное
  изображение с bbox (цвет = класс) → количество по видам сорняков, total
  detections, weed coverage %, время обработки.
- **🎥 Видео / камера (наземная станция)** — тот же пайплайн покадрово: на
  вход видеофайл или индекс видеоустройства (веб-камера / карта
  видеозахвата). См. раздел «Архитектура для реального дрона» ниже.
- **ℹ️ Архитектура для дрона** — пояснение, как это подключается к
  реальному UAV.

В сайдбаре — слайдер confidence threshold и переключатель режима
инференса:

- **Tiled UAV inference** (по умолчанию) — изображение режется на
  перекрывающиеся тайлы, детекция выполняется на каждом тайле, боксы
  пересчитываются в координаты исходного изображения и объединяются
  через NMS. Предназначен для больших снимков с дрона.
- **Standard inference** — один проход по всему изображению.

## Архитектура для реального дрона (DJI O4)

**DJI O4 — это система видеопередачи** (4-е поколение OcuSync), а не
бортовой компьютер: у неё нет вычислительного модуля, и запустить на ней
модель детекции невозможно в принципе.

Реалистичная схема для UAV-сценария — **вычисления на земле**:

1. Дрон снимает поле и передаёт видео через O4 на пульт/очки.
2. Наземная станция (ноутбук/мини-ПК) принимает сигнал — через карту
   видеозахвата (HDMI-выход пульта → USB capture card → в системе
   выглядит как обычная веб-камера) либо программно через DJI SDK/RTMP.
3. Вкладка **«🎥 Видео / камера»** в `app.py` принимает именно такой
   источник (индекс устройства или видеопоток) и прогоняет через него ту
   же модель покадрово, с тем же tiled-инференсом для крупных кадров.
4. Результат — боксы, статистика, % засорённости — отображается на земле
   в реальном времени.

Перенос модели непосредственно на борт дрона потребовал бы отдельного
бортового компьютера (например, Jetson) — сознательно вне периметра
этого хакатон-MVP.

## Структура проекта

```
app.py                    # Streamlit web-демо (фото / видео / архитектура)
src/prepare_dataset.py    # генерация YOLO-разметки из classification-датасета
src/train.py               # обучение YOLOv8
src/tiled_inference.py    # тайлинг + NMS-объединение детекций
src/inference.py           # загрузка модели, единая точка входа standard/tiled
src/visualize.py           # отрисовка боксов, расчёт coverage %
data/                       # сгенерированный YOLO-датасет (data.yaml, images/, labels/) — .gitignore
models/best.pt              # обученные веса (появляются после train.py)
runs/                       # логи и артефакты обучения ultralytics — .gitignore
Сорняки/                    # исходный датасет (виды сорняков, без bbox)
Поля/                       # реальные тестовые снимки с дрона DJI (без разметки)
```

## Известные ограничения

- Bbox-разметка получена автоматически (ExG-сегментация), а не вручную —
  это приближение, а не точная разметка объектов. Для продакшна нужна
  ручная разметка хотя бы части датасета.
- Обучение и данные не различают фазу роста (розетка/стеблевание) —
  только вид сорняка, т.к. этого требует ТЗ.
- **Подтверждённый domain-shift**: обучающие фото — это макросъёмка, где
  растение занимает почти весь кадр, поэтому и псевдо-bbox почти всегда
  близки к размеру всего кадра. При прогоне через tiled-инференс на
  реальных снимках с дрона (`Поля/`) модель по инерции размечает целыми
  тайлами вместо локализации отдельных растений — коробки почти на весь
  тайл, coverage % завышен. Это ограничение данных (нет реальной
  UAV-разметки), а не баг пайплайна: тайлинг, NMS-объединение и вся
  цепочка инференса работают корректно, что подтверждено визуально.
  Для продакшна нужна ручная разметка хотя бы части реальных дрон-фото.
- Обучение выполнялось на CPU (в окружении нет GPU) — при наличии CUDA
  используйте `--device 0` для ускорения.
- Live-видео режим — синхронный покадровый цикл с жёстким лимитом кадров
  за сеанс (настройка в сайдбаре), не полноценный realtime-стрим: на CPU
  один tiled-проход по крупному кадру занимает секунды, поэтому реального
  видео-FPS не будет — это демонстрация архитектуры «наземная станция
  принимает видеопоток и гоняет через ту же модель», а не production
  realtime-пайплайн.
