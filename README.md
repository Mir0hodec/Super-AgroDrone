# AgroDrone Weed Detector — MVP детекции сорняков на снимках с дрона

Хакатонный MVP: детекция сорняков (YOLOv8) на снимках с полей, с тайловым
инференсом для больших UAV-изображений, определением фазы вегетации,
рекомендацией по обработке и веб-демо на Streamlit.

## Данные

Исходный датасет `Сорняки/<Вид сорняка>/<Фаза роста>/*.jpg` — это
классификационный набор (кропы отдельных растений), **без bounding box
разметки**. Чтобы получить рабочий детектор, `src/prepare_dataset.py`
автоматически генерирует псевдо-bbox для каждого фото: растение
сегментируется по индексу избыточной зелени (ExG) с порогом Отсу, берётся
bounding rect найденного объекта (с fallback на центральную область
кадра, если сегментация не удалась).

**Классы детектора = "<вид сорняка> / <фаза роста>"** (5 классов) — одна
детекция сразу даёт и вид, и стадию вегетации:

- Бодяк полевой / Розетка, Стеблевание
- Вьюнок полевой / Розетка, Стеблевание
- Пырей ползучий / Стеблевание

`Поля/*.JPG` — пять реальных снимков с дрона DJI (4096×3072), без
разметки. Для обучения не используются (нет меток), но служат тестовым
набором для проверки tiled-инференса на настоящих UAV-кадрах и как
готовые примеры в веб-демо.

## Быстрый старт

```bash
git clone https://github.com/Mir0hodec/Super-AgroDrone.git
cd Super-AgroDrone
pip install -r requirements.txt
python src/prepare_dataset.py
python src/train.py
streamlit run app.py
```

`models/best.pt` уже лежит в репозитории (baseline, обучен на слабом
CPU-only ПК, mAP50 ≈ 0.87 на валидации) — можно сразу `streamlit run
app.py` без переобучения. Ниже — как дообучить нормально на GPU.

На Windows шаги 2-4 (install → prepare_dataset → train) можно выполнить
одной командой: `setup_and_train.bat` (доп. флаги пробрасываются в
`train.py`, например `setup_and_train.bat --epochs 200 --model yolov8s.pt`).

## Обучение на мощном ПК (GPU)

Это главное, что стоит сделать при переезде на более сильную машину —
`src/train.py` сам определяет, есть ли CUDA, и на GPU подставляет
адекватные epochs/imgsz/batch вместо CPU-заглушек. Но есть одна ловушка:

> **`pip install torch` на Windows по умолчанию с PyPI часто ставит
> CPU-сборку**, даже если видеокарта есть — PyPI не хостит там
> CUDA-сборки для Windows из-за размера. Из-за этого GPU просто не будет
> использоваться, и вы не поймёте почему.

Проверить и поставить правильно:

```bash
# 1. Убедиться, что видеокарта и драйвер видны системе
nvidia-smi

# 2. Проверить, что видит PyTorch (после pip install -r requirements.txt)
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Если `torch.cuda.is_available()` вернул `False`, а `nvidia-smi` видеокарту
видит — переустановите torch с CUDA-сборкой (версию `cuXXX` смотрите на
https://pytorch.org/get-started/locally/ под свою версию драйвера, обычно
подходит `cu121` или новее):

```bash
pip uninstall -y torch torchvision
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
python -c "import torch; print(torch.cuda.is_available())"   # должно стать True
```

После этого — обучение:

```bash
python src/prepare_dataset.py
python src/train.py
```

На GPU скрипт сам возьмёт `epochs=150`, `imgsz=640`, `batch=16`,
`device=0`. Параметры переопределяются флагами:

```bash
python src/train.py --epochs 200 --imgsz 640 --batch 32 --model yolov8s.pt
```

- `--model yolov8n/s/m/l/x.pt` — крупнее модель = точнее, но медленнее;
  на GPU можно смело брать `yolov8s.pt` или `yolov8m.pt` вместо `yolov8n.pt`.
- `--device 0` — явно первая видеокарта, `--device cpu` — явно CPU.

Лучшие веса сохраняются в `models/best.pt` (перезаписывают текущие).

### Что реально даст переезд на GPU

Baseline (`models/best.pt` в репозитории) обучен 25 эпохами на CPU —
этого хватило дойти до mAP50 ≈ 0.87 на валидации (кропы растений), но на
**реальных снимках с дрона** (`Поля/`) видовая классификация путается —
классический domain-shift (макросъёмка ≠ аэрофото), подробнее в разделе
«Известные ограничения». GPU сам по себе эту проблему не решит — он
решает только скорость (можно позволить себе больше эпох/побольше модель/
больше разрешение). Настоящее решение domain-shift — доразметка хотя бы
части реальных UAV-фото и дообучение на них; это следующий шаг, а не то,
что можно получить бесплатно от более сильного железа.

## Проверка инференса из консоли

```bash
python src/inference.py path/to/image.jpg 0.25 tiled
```

Сохранит `path/to/image_pred.jpg` и напечатает статистику (кол-во по
классам, total detections, weed coverage %, время обработки).

## Веб-демо

```bash
streamlit run app.py
```

Три способа получить снимок:

- **📸 Примеры с дрона** — 5 реальных фото из `Поля/`, встроены в
  приложение (миниатюры в `assets/thumbs/`) — можно сразу посмотреть, как
  это работает, без своих файлов.
- **⬆️ Загрузить со своего компьютера** — обычная загрузка файла.
- **🗂️ Папка на компьютере** — реальный рабочий сценарий: снимки с
  SD-карты дрона скопированы в папку на ноутбуке, путь указывается вручную,
  приложение находит все `.jpg/.png` в ней.

После детекции: снимок / результат с рамками (цвет = вид), число найденных
сорняков, % засорённости, время обработки, разбивка по видам и фазам, и
для каждого найденного класса — рекомендуемые группы гербицидов
(`src/weed_info.py`, справочные данные, не инструкция по применению).

В сайдбаре — чувствительность обнаружения (confidence threshold) и режим:

- **Крупный снимок с дрона (по частям)** — тайловый инференс (по
  умолчанию): изображение режется на перекрывающиеся квадраты, детекция
  выполняется на каждом, боксы пересчитываются в координаты исходного
  снимка и объединяются через NMS. Для больших UAV-кадров.
- **Обычное фото (целиком)** — один проход по всему изображению.

## Архитектура для реального дрона (DJI O4)

**DJI O4 — это система видеопередачи** (4-е поколение OcuSync), а не
бортовой компьютер: у неё нет вычислительного модуля, и запустить на ней
модель детекции невозможно в принципе.

Рабочая схема — **вычисления на земле**: дрон фотографирует поле → снимок
переносится на компьютер (карта памяти / приложение DJI / кабель) → этот
компьютер запускает `app.py`, который и анализирует фото. Перенос модели
непосредственно на борт дрона потребовал бы отдельного бортового
компьютера (например, Jetson) — сознательно вне периметра этого MVP.

## Структура проекта

```
app.py                     # Streamlit web-демо
src/prepare_dataset.py     # генерация YOLO-разметки из classification-датасета
src/train.py                # обучение YOLOv8 (auto GPU/CPU)
src/tiled_inference.py     # тайлинг + NMS-объединение детекций
src/inference.py            # загрузка модели, единая точка входа standard/tiled
src/visualize.py            # отрисовка боксов, расчёт coverage %
src/weed_info.py            # справочник по видам: тип, гербициды, фаза-заметки
assets/thumbs/               # миниатюры примеров для веб-демо
data/                        # сгенерированный YOLO-датасет — .gitignore, генерируется заново
models/best.pt               # обученные веса (в репозитории — baseline с CPU)
runs/                        # логи и артефакты обучения ultralytics — .gitignore
Сорняки/                     # исходный датасет (виды сорняков, без bbox)
Поля/                        # реальные тестовые снимки с дрона DJI (без разметки)
```

## Известные ограничения

- Bbox-разметка получена автоматически (ExG-сегментация), а не вручную —
  это приближение, а не точная разметка объектов. Для продакшна нужна
  ручная разметка хотя бы части датасета.
- **Подтверждённый domain-shift**: обучающие фото — это макросъёмка
  отдельных растений. На реальных снимках с дрона (`Поля/`) после полного
  обучения (25 эпох) локализация стала адекватной (рамки вокруг отдельных
  кустиков, а не целых тайлов, как было на недообученной модели), но
  **видовая классификация путается** — большая часть зелени размечается
  одним доминирующим классом. Тайлинг и NMS-объединение работают
  корректно — ограничение именно в характере обучающих данных (нет
  реальной UAV-разметки), не в пайплайне.
- Гербициды в рекомендациях — общая агрономическая справка для демо, не
  инструкция по применению конкретного препарата.
- `models/best.pt` в репозитории обучен на CPU (в исходном окружении не
  было GPU) — см. раздел «Обучение на мощном ПК» выше, чтобы дообучить
  нормально.
